# Contributing

Tie a change to a concrete supported profile or observed defect. A new blocking predicate needs a primary source, explicit applicability, typed evidence shape, positive/negative/incomplete cases and a clear authority boundary. Put workload-dependent preferences in guidance until measurable project requirements justify a check.

Run unit tests and `eng/qualify.py`; run the pinned disposable native lane when engine behavior or collection changes. Record unavailable lanes and unexpected survivors. Keep snapshot/command/provenance limits visible and preserve existing failures when evidence is incomplete.

Update the mirrored skill and its source ledger together with the central CanonFlowFoundation/skills copy. The auditor source and catalogues are self-contained; sibling checkouts are not runtime dependencies. Do not connect tests to an existing production database or alter host daemon/sysctl configuration.
